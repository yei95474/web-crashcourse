# Glossary

[Course home](../HTML_CRASH_COURSE.md)

## A

**Access key**  
A browser-mediated keyboard shortcut requested with `accesskey`; key combinations vary and can conflict with user or assistive-technology shortcuts.

**Absolute URL**  
A complete URL containing a scheme and host, such as `https://example.org/about`.

**Accessibility**  
The practice of making content and interaction usable by people with a wide range of abilities, technologies, and situations.

**Accessible name**  
The text by which assistive technology identifies an element, obtained from sources such as visible labels, button content, link content, or alternative text.

**Ancestor**  
Any node above another node in the document tree: its parent, parent's parent, and so on.

**ARIA**  
Accessible Rich Internet Applications, a set of attributes that supplements accessibility semantics when native HTML is insufficient.

**Attribute**  
Information written in an opening tag, usually as a name-value pair: `lang="en"`.

**Attribution**  
Credit identifying a work, creator, source, license, and relevant modifications according to the applicable terms.

**Autocapitalization**  
A virtual-keyboard hint, supplied with `autocapitalize`, suggesting whether and how text should be capitalized.

**Autocomplete**  
A form attribute describing what real-world information a value represents so a browser can offer appropriate saved data.

## B

**Boolean attribute**  
An attribute whose presence represents true and absence represents false, such as `required`.

**Browser**  
Client software that requests, parses, and presents web resources.

## C

**Caption**  
Visible text identifying or explaining a table or figure, represented by `caption` or `figcaption`.

**Capture hint**  
A file-input hint that may request direct camera or microphone capture in supporting device contexts.

**Character encoding**  
A mapping between stored bytes and characters. UTF-8 is the standard choice for course documents.

**Character reference**  
HTML source syntax representing a character, such as `&lt;` for `<`.

**Child**  
A node directly contained by another node.

**Class**  
A reusable space-separated classification stored in the global `class` attribute.

**Client**  
Software that requests a service or resource; a browser is a web client.

**Constraint validation**  
Browser checks created by form attributes such as `required`, `min`, and `pattern`.

**Content model**  
Rules describing what kinds of content an element can contain and where it may occur.

**Content Security Policy (CSP)**  
A policy, normally sent through HTTP headers, restricting resource sources and selected document capabilities.

**Custom element**  
An element with a hyphenated name whose custom behavior is defined through JavaScript.

## D

**Declaration (doctype)**  
The `<!doctype html>` instruction that selects modern HTML parsing behavior.

**Data minimization**  
Collecting only personal information necessary for a defined task.

**Datalist**  
An element supplying suggestions to a compatible input while normally allowing other values.

**Decoding hint**  
An image attribute indicating preferred synchronous, asynchronous, or automatic decoding behavior.

**Descendant**  
Any node nested below another node.

**Directory**  
A folder that groups files and other directories.

**Diagnostic assessment**  
A low-stakes check used to identify existing knowledge and choose suitable instruction, not to exclude beginners.

**Document Object Model (DOM)**  
The structured programming interface and tree representation created from a document.

**Document-relative path**  
A path calculated from the current document's directory.

## E

**Element**  
A node or conceptual HTML unit represented by tags and content, or by one void-element tag.

**Embedding**  
Including an external resource or nested page through elements such as `img`, `video`, or `iframe`.

**Encoding**  
See character encoding.

**Enter-key hint**  
The `enterkeyhint` attribute's suggestion for a virtual keyboard's Enter-key label or action.

## F

**Fallback content**  
Alternate content available when a preferred resource or feature cannot be used.

**Fragment**  
The part of a URL beginning with `#`, commonly targeting an element ID within a document.

**Form owner**  
The `form` element associated with a form control, either by ancestry or an explicit `form` attribute.

**Fetch priority**  
A hint describing a resource's relative fetch importance among comparable resources.

## G

**GET**  
An HTTP method used for retrieval. Form GET data is commonly encoded in the URL query.

**Global attribute**  
An attribute allowed on all HTML elements, though not necessarily useful on all.

## H

**Heading hierarchy**  
The logical organization formed by `h1` through `h6`.

**Host**  
The URL component identifying the server, such as `example.org`.

**Hidden until found**  
A specialized hidden state that supporting browsers can reveal through find-in-page or fragment navigation.

**Hreflang**  
Metadata describing the human language of a linked resource, commonly used for separately published language alternatives.

**HTML**  
HyperText Markup Language, the language used to structure and give meaning to web content.

**HTTP**  
Hypertext Transfer Protocol, used for communication between web clients and servers.

**HTTPS**  
HTTP protected in transit by TLS encryption and server identity mechanisms.

## I

**ID**  
A unique identifier assigned through the global `id` attribute.

**Information architecture**  
Organization and labeling that help people find and understand content.

**Implementation**  
A browser or other software's working realization of behavior described by a standard.

**Inert**  
Unable to receive normal focus or interaction and omitted from ordinary accessibility navigation as part of an inert subtree.

**Input mode**  
A hint about the most useful virtual keyboard or input modality for an editable control.

**Intrinsic dimensions**  
An image's inherent width and height, which can be supplied to the browser with `width` and `height`.

## K

**Keyboard accessibility**  
The ability to reach, understand, and operate content without a pointing device.

## L

**Landmark**  
A major page region exposed for navigation, such as main content or primary navigation.

**Lazy loading**  
Deferring an off-screen resource until the browser predicts it will be needed.

**Link text**  
The content naming an anchor's destination or purpose.

**License**  
Terms under which a rights holder permits specified uses of a work.

**Living Standard**  
A standard maintained continuously rather than replaced only through infrequent numbered editions.

**Local file**  
A file read from the user's computer rather than requested from a public web server.

## M

**Markup language**  
A language that annotates content with structure or meaning.

**Metadata**  
Information about a document, commonly stored in `head`.

**Media type (MIME type)**  
A resource classification such as `text/html` or `image/png` communicated through HTTP or related metadata.

## N

**Name-value pair**  
A field name associated with a submitted value.

**Native element**  
An HTML element whose built-in semantics and behavior match a content or interface need.

**Nesting**  
Placing one element inside another.

**Node**  
One item in a document tree, such as an element or text node.

## O

**Obsolete feature**  
Markup no longer conforming for modern authoring, often replaced by semantic HTML, CSS, or newer APIs.

**Origin**  
The combination of scheme, host, and port used in web security boundaries.

## P

**Parent**  
A node that directly contains another node.

**Parsing**  
Converting source text into a structured representation according to language rules.

**Path**  
Directions identifying a resource location.

**Percent encoding**  
URL syntax representing a byte with `%` followed by two hexadecimal digits, such as `%20` for an encoded space.

**Performance**  
How efficiently and responsively a page loads, renders, and reacts under real user conditions.

**POST**  
An HTTP method commonly used to submit data that creates or changes server state.

**Progressive enhancement**  
Starting with a functional foundation and adding supported enhancements without making the foundation unusable.

## Q

**Quirks mode**  
A legacy browser rendering mode that imitates selected old behaviors, commonly triggered by a missing or unsuitable doctype.

**Query**  
The URL component beginning with `?`, often containing request parameters.

## R

**Relative path**  
Resource directions interpreted from a base location rather than a complete absolute URL.

**Referrer policy**  
A policy controlling how much referring-page information accompanies a request.

**Request**  
A client's message asking a server to perform an action or return a resource.

**Responsive image**  
An image setup that offers candidates for different resolutions, layouts, or art direction.

**Response**  
A server's reply containing status, headers, and often a resource representation.

**Root element**  
The top document element; `html` is the root of an HTML document.

**Ruby annotation**  
Small pronunciation or explanatory text associated with base text, commonly using `ruby` and `rt`.

## S

**Screen reader**  
Assistive technology that presents interface information through speech or braille.

**Search landmark**  
A page region containing controls or content for searching or filtering.

**Semantic HTML**  
Markup selected according to content purpose and meaning.

**Server**  
Software that listens for requests and provides responses.

**Sibling**  
Nodes sharing the same parent.

**Source**  
The text written by an author before or as interpreted by a browser.

**Specification**  
An authoritative technical document defining requirements and behavior for a technology.

**Standards mode**  
The browser's modern document-rendering mode, selected for HTML pages by `<!doctype html>`.

**Syntax**  
Rules governing how a language is written.

**Structured data**  
Machine-readable facts about entities such as events, products, or organizations, kept consistent with visible content.

**Subresource Integrity (SRI)**  
A mechanism allowing a browser to verify a fetched script or stylesheet against an expected cryptographic hash.

## T

**Tab order**  
The sequence in which focus moves through interactive elements.

**Tag**  
Source syntax inside angle brackets, such as `<p>` or `</p>`.

**Text alternative**  
Text serving the purpose of non-text content for users who cannot perceive it.

**Template**  
An inert HTML fragment held for later use, commonly cloned by JavaScript.

**Tree**  
A hierarchical data structure with parent-child relationships.

## U

**URL**  
Uniform Resource Locator, an address identifying a resource and access method.

**UTF-8**  
A widely used Unicode character encoding suitable for HTML documents.

**User-agent stylesheet**  
The browser's built-in CSS that gives unstyled elements their initial presentation.

## V

**Validation**  
Checking content against rules or constraints.

**Validator**  
A tool that checks markup conformance.

**Viewport**  
The browser area through which a document is viewed; mobile browsers also use a layout viewport configured through metadata.

**Void element**  
An element that cannot contain child content and has no closing tag, such as `img`.

## W

**Web**  
The system of interlinked resources accessed through web technologies over the Internet.

**Web app manifest**  
A JSON resource linked from HTML that describes application names, icons, display preferences, and related metadata.

**Webpage**  
One web document or resource presented as a page.

**Website**  
A related collection of webpages and resources.

**Whitespace**  
Spaces, tabs, and line breaks in source.
