# HTML Crash Course, Second Edition

## From absolute beginner to confident HTML author

Current release: **2.1 (2026-07-14)**. See [edition history and errata](reference/edition-history-and-errata.md).

Welcome. This book assumes that you have never built a website and may never have written code. It starts with files, browsers, and the basic idea of the Web. It then develops HTML one idea at a time until you can plan, build, inspect, and improve a complete multi-page website.

HTML is the language that gives web content structure and meaning. CSS controls presentation. JavaScript adds programmable behavior.

```text
HTML       -> What is this content?
CSS        -> How should it look?
JavaScript -> What should it do?
```

The goal is not to memorize every element. The goal is to learn how to reason about documents: how parts relate, how a browser interprets markup, how meaningful structure helps people and software, and how to diagnose mistakes.

The 20 numbered chapters form the required beginner path. Three optional appendices extend the book into performance, security, privacy, less-common platform features, browser testing, and assistive-technology orientation without making the core progression denser.

## Who this book is for

You need no programming experience, advanced mathematics, or computer-science background. You should be able to:

- Create, rename, and move files and folders.
- Use a keyboard and web browser.
- Install or open a text editor.
- Practice for at least 30 minutes at a time.

If file management is unfamiliar, Chapter 2 teaches exactly what you need.

## Required tools

- A computer running Windows, macOS, or Linux.
- A modern browser such as Edge, Chrome, Firefox, or Safari.
- A plain-text code editor. Visual Studio Code is used in examples, but another editor is acceptable.
- A workspace folder for your exercises.

No paid software, web server, framework, or account is required. Git, GitHub, CSS, JavaScript, and deployment appear only as next steps.

## What you will be able to do

After completing the course, you should be able to:

1. Explain how a browser obtains and displays a webpage.
2. Create valid HTML documents with useful metadata.
3. Structure text, links, navigation, media, tables, and forms.
4. Choose semantic elements based on meaning rather than appearance.
5. Build pages that work for keyboard and assistive-technology users.
6. Organize a consistent multi-page website.
7. Debug broken paths, malformed markup, and accessibility problems.
8. Read standards and reference documentation when you meet unfamiliar HTML.
9. Evaluate your own work with a professional rubric.
10. Continue into CSS, JavaScript, version control, and deployment.

## How the course teaches

Each chapter follows a predictable sequence:

1. **Study time and prerequisites** - what to know and approximately how long to plan.
2. **Vocabulary** - words you need before the explanation.
3. **Context** - why the topic matters.
4. **Concepts** - new material from simplest to hardest.
5. **Worked examples** - small examples with explanations.
6. **Practice** - questions, puzzles, and guided construction.
7. **Challenge** - a cumulative task using earlier material.
8. **Review** - misconceptions, summary, and mastery checklist.

Exercises have stable IDs such as `C04-Q3`. Use these IDs to find explanations in the answer keys.

### Difficulty labels

- **Warm-up**: recall one fact or complete one missing part.
- **Core challenge**: combine the chapter's main ideas.
- **Stretch challenge**: reason across several chapters or research a new detail.

Do not open an answer key immediately after getting stuck. First reread the nearest example, inspect your spelling and nesting, and test one small change. Productive struggle is part of learning; endless frustration is not.

## Suggested schedules

These schedules are guides, not deadlines. A chapter is complete when you can perform its mastery checklist without relying heavily on the examples.

### Four-week intensive

| Week | Chapters | Main result |
| --- | --- | --- |
| 1 | 1-5 | First document and About Me page |
| 2 | 6-10 | Linked recipe or hobby site |
| 3 | 11-15 | Accessible event-registration page |
| 4 | 16-20 | Multi-page capstone and review |

Plan for 90-120 minutes on most days.

### Eight-week standard

| Week | Chapters | Focus |
| --- | --- | --- |
| 1 | 1-3 | Web, tools, first document |
| 2 | 4-5 | Syntax and text |
| 3 | 6-7 | Links, navigation, lists |
| 4 | 8-10 | Media and semantic structure |
| 5 | 11-12 | Tables and forms |
| 6 | 13-15 | Validation, metadata, accessibility |
| 7 | 16-18 | Advanced HTML and debugging |
| 8 | 19-20 | Capstone |

Plan for 45-75 minutes on five days each week.

### Twelve-week steady

Study one or two chapters per week. Reserve Weeks 4, 7, 10, and 12 for project work and cumulative review. This pace suits students balancing the course with school or employment.

Whichever schedule you choose, reserve a separate 2-3 hour session after Chapter 20 for the final assessment. The capstone itself should be built across several sessions rather than as a timed typing exercise.

## Standards and version policy

This book teaches the living web platform rather than an old numbered version called “HTML5.” Durable principles receive the most attention. Newer or less familiar features are marked advanced and should be checked against current browser documentation before production use.

Primary learning references are the [WHATWG HTML Living Standard](https://html.spec.whatwg.org/multipage/), [MDN Learn Web Development](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Structuring_content), and [W3C Web Accessibility Initiative tutorials](https://www.w3.org/WAI/tutorials/).

Each chapter ends with topic-specific authoritative references. Less-common or rapidly changing features are placed in optional appendices and should be checked against current compatibility data before production use.
